# SWLOR reload decisions: what a hot reload runs in place of each boot-only handler, and the state it adopts.
# Boot-only handlers in manifest order: adopt <step> [carry <step>] = the reload bootstrap runs the adoption step after
# the rerun handlers (and the old build ran the carry step while it quiesced); nothing = why a reload needs nothing.
# Rerun handlers with an adoption step: it puts back, after the reruns, what the rerun rolled anew.
# Adopted state: the fields marked [ReloadState(ReloadStateKind.Adopted)], compared with the old build's at quiescence.
# Rerolled state: the fields marked [ReloadState(ReloadStateKind.Rerolled)], rolled again by a reload and not compared.
# Carried state: the fields marked [ReloadState(ReloadStateKind.Carried)], written by the old build at quiescence and read back
# by the new one after its adoptions (ReloadStateCarrier), compared with the old build's at quiescence.
# The rule is in SWLOR.Game.Server/Readmes/MaintainabilityRefactorHotReload.md sections 2 and 3.
# Regenerate (build first): SWLOR_UPDATE_SNAPSHOTS=1 dotnet test SWLOR.Game.Server.Tests --no-build --filter "FullyQualifiedName~ReloadAdoptionTests"   (PowerShell: $env:SWLOR_UPDATE_SNAPSHOTS='1'; dotnet test ...; Remove-Item Env:SWLOR_UPDATE_SNAPSHOTS)

  nothing: The module, area and NWNX event bindings and the legacy item property hook stay in the engine; the reload bootstrap reruns the cache scripts' rerun handlers itself.

  nothing: A reload sends no boot notification.
