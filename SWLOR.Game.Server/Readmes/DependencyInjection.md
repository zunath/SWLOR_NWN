# Dependency Injection

How the server's services are instance classes built by a dependency-injection container, and how to convert one. The decisions are in `MaintainabilityRefactorSpecs.md` (Phase 2); this guide is the working recipe, with the pilot (`Achievement`, `Faction`, `Taxi`) as the example. Read it before converting a service. There are no static facades: a service is its instance class, its interface and a `GameServices` property.

Sections: The pattern · The container · Converting a service · Dependencies · Tests · Rules the architecture tests enforce · Reaching a service from static code · Pitfalls · A service of several classes

## The pattern

A converted service is four pieces.

| Piece | Where | What it is |
|---|---|---|
| Interface | `Domain/<Domain>/I<Name>Service.cs` | One member per public member of the service, with the doc comments. |
| Instance class | `Domain/<Domain>/<Name>Service.cs` | The logic. State is instance fields; dependencies come through the constructor. It holds the `[NWNEventHandler]` methods (public, parameterless instance methods) and the public `const` fields. |
| Registration | `Composition/ServiceRegistrations.cs` | One line registering the interface as a singleton. |
| Property | `Composition/GameServices.<Domain>.cs` | `public static I<Name>Service <Name> => FacadeAccessor.Resolve<I<Name>Service>();`, which static code (content definitions, native hooks, tools, tests) reaches the service through. |

`<Domain>` is the domain the service is in `SWLOR.Architecture.Tests/DomainMap.json` (Core, UI, Combat, Abilities, Character, Items, Crafting, Economy, Quests, World, Space, Creatures, Companions, Social, Administration, Gameplay). The namespace is `SWLOR.Game.Server.Domain.<Domain>`, never `SWLOR.Game.Server.<Domain>`: a namespace named like a service (`Combat`, `Space`) or like an existing folder (`Core`) would capture simple names such as `Combat.CalculateHitRate()` in every file below `SWLOR.Game.Server`. For the same reason a service whose name is also a namespace segment (`Combat`, `Mimicry`, `Performance`, `Prospecting`) is written `GameServices.Combat` where it is called.

The support types of the service (the enum, the attribute, records) stay where they are, in `Service/<Name>Service/`; they move to `Domain.<Domain>` in P2-Z2.

The instance class, as converted (`Domain/Character/AchievementService.cs`):

```csharp
public class AchievementService : IAchievementService
{
    private readonly IDBService _db;

    public AchievementService(IDBService db)
    {
        _db = db;
    }

    [NWNEventHandler(ScriptName.OnModuleLoad)]
    public void ReserveGuiIds()
    {
        // ...
    }

    public void GiveAchievement(uint player, AchievementType achievementType)
    {
        // ...
    }
}
```

A public `const` lives on the instance class (`public const int MinimumFaction` on `Domain.Quests.FactionService`), and callers name that class: spell the namespace, because `FactionService` alone means the namespace `SWLOR.Game.Server.Domain.Quests` inside `namespace SWLOR.Game.Server.Service`. Compile-time constants are inlined, so the toolset is unaffected.

## The container

Code lives in `Composition/`.

- `ContainerHost` builds a container once, with `ValidateOnBuild` and `ValidateScopes`, and creates every singleton during the build. A missing dependency, a lifetime mistake or a constructor that throws stops the boot, not the first handler that needs the service. A second build, or asking before the build, throws `ContainerNotBuiltException`.
- `CompositionRoot.ServerHost` is the server's container. `ServiceRegistrations` lists the services, one line each, grouped by domain. Every game service is a singleton (process lifetime; there are no scoped services in this phase).
- `FacadeAccessor.Resolve<T>()` is the one internal accessor, used by the `GameServices` properties. Nothing else outside `Composition/` may resolve from the container (see the rules below).
- `ServerBootstrapper` runs a named step list (`Steps`). `BuildServiceContainer` comes after the internal systems (logging, the script execution provider) and before `RegisterEventHandlers`, `LoadEngineTestAssembly` and `LoadScripts`. Handlers exist only after `LoadScripts` registers them, and the engine cannot call back into the server before `Bootstrap` returns, so the container exists before any handler, `mod_preload` included. `LoadScripts` refuses to run without the container, and `ServerBootstrapperOrderTests` pins the order.
- A constructor must not call the engine or read other services' state: singletons are created while the server boots, before the module loads. Do engine-dependent setup in a handler, as the services always did.

A `GameServices` property reads a per-service cache (`Composition/FacadeCache<T>`) instead of asking the container on every call: one static slot per service type holds the instance and the container it came from. A call compares that container with `CompositionRoot.Current` (reference check) and returns the instance from the slot, with no dictionary lookup and no allocation. The slot is valid only for its own container, so nothing needs clearing: when the container is built, replaced or rebuilt (Phase 4 hot reload), or a test installs its own, `Current` names another container, the check fails and the next call resolves and refills the slot. A cached instance is therefore never served for a container that is no longer current, and fixtures that install different `FacadeContainer`s are safe, also when they run in parallel (they refill the slot, which costs one container lookup). Two threads that miss together both resolve and both write; services are singletons, so both get the same instance and the race is benign. Before the container exists `Current` throws `ContainerNotBuiltException`. Measured with `Bank.IsFull` in Release (`FacadeCacheTests.Measure_facade_call_cost`, an explicit test): about 8-9 ns per call through `GameServices` against about 4 ns for a direct instance call, down from about 26 ns before the cache.

Tests that need their own container build one with `ContainerHost.Create(services)` and make `GameServices` use it for the current async flow with `CompositionRoot.InstallForTests(provider)`. Production code never calls it (`CompositionSourceGuardTests` fails if it does).

## Converting a service

One service per pull request. Each pull request also brings the service's own lines to at least 70% coverage.

1. Read the service, its folder, its callers (the service's edges in `SWLOR.Architecture.Tests/Baseline/CrossDomainEdges.txt`), its handlers (`Core/ScriptHandlerOrder.txt`) and its tests. Look for tests that recompile its source with Roslyn or reset its static state by reflection; they are replaced in step 7.
2. Create the interface and the instance class in `Domain/<Domain>/`. Move the logic and state verbatim: statics become instance fields, `static` goes off the methods (private helpers included), nothing else changes. A `const` moves with the logic; a public one stays on the instance class and callers name that class. A public static property becomes an interface property. Keep strings that name the service (a GUI id reservation made under `nameof(Achievement)` stays the literal `"Achievement"`).
3. Move each `[NWNEventHandler]` onto a public parameterless instance method of the instance class (or of the part that owns it): the script registry binds it to the container's singleton. Rename its line in place in `Core/ScriptHandlerOrder.txt` (`SWLOR.Game.Server.Service.Taxi.LoadTaxiDestinations` becomes `SWLOR.Game.Server.Domain.World.TaxiService.LoadTaxiDestinations`, same position) and add `<master full name> <branch full name>` to `tools/Refactor/HandlerRenames.txt` in the same pull request, so the parity run and the master sync match it by the branch name.
4. Register the interface in `Composition/ServiceRegistrations.cs` (one line), add the property to `Composition/GameServices.<Domain>.cs`, and add the service, sorted by name, to `SWLOR.Architecture.Tests/ConvertedServices.json`.
5. Change each static caller to the property (see "Reaching a service from static code"), and list the old static class in `tools/Refactor/RemovedFacades.json` (sorted; `"explicit": true` for the four namespace-segment names; `"constants"` with each constant's new owner; for a class whose members went to several classes, `"members"` with each owner and its names: a name under two owners is an overload on each, which the tool leaves for a person) so the daily sync keeps master's calls to it compiling.
6. If the old file made player messages, `Readmes/PlayerMessageAudit.json` lists them by file: change `File` (and `Line`) of those entries to the instance file. If `PlayerMessageAuditTests` names the old file in its list of gameplay-outcome files, name the instance file.
7. Write the unit tests (below) and measure coverage.
8. Build and run: the service's tests, `SWLOR.Architecture.Tests`, `SWLOR.Game.Server.CharacterizationTests` (snapshots must not change), the handler order tests (`ScriptHandlerManifestOrderTests`, `ScriptHandlerSeamTests`), and `scripts/ci/run-unit-tests.sh --out <dir>`. For a service with in-game behaviour also run the engine characterization scenarios (`scripts/run-engine-tests.ps1 -Filter Characterization`, `EngineTesting.md`).
9. Record the service, the pull request and the coverage before and after in `MaintainabilityRefactorStatus.md` (the coordinating session does this when it merges).

## Dependencies

| The service uses | In the instance class |
|---|---|
| Another converted service | Constructor-injected interface. |
| A static class that is not a service (`Space`, `Droid`, `Log`, `Random`, `Time`, ...) | A direct static call, as before. |
| `DB` | `IDBService` (`Domain/Foundation`), implemented by `DBService`, constructor-injected. The `OnModulePreload` handler is on `DBService`. The Redis connection, entity cache, write versions and index metadata are instance state. Members that only static code needs (`Load`, `StreamAdd`, `GetRawJson`, `SearchIds`, `SearchRawJson`, `SetUnindexedJsonProperty`, `EscapeTokens`) have a default that throws, so a fake implements only what its test uses (`InMemoryDBService`). A tool that has no game server (`SWLOR.CLI`, `SWLOR.Admin`) builds the container with `CompositionRoot.Build(CompositionRoot.ServerHost)` before `GameServices.DB.Load()`. Unit tests of the service use `FakeRedis` through the protected virtual seams. |
| The engine (NWScript, NWNX) | Bare calls through the global static imports, as everywhere. Tests swap the engine with `NWScriptRuntime.Override` and the plugin runtimes (`PlayerPluginRuntime.Override`, ...). Do not inject `INWScript`. |
| Native engine objects (`NWNXLib.g_pAppManager`, `CNWSPlayer`, ...) | Not seamed yet. Put each read of native data in a small `protected virtual` method of the instance class whose body is the original code, and let a test subclass answer it. Return a managed value (a record struct, an `int?`) instead of the native object when the rest of the logic needs only a few fields (`ChatPortraitTellsClient`). Keep the native read to the smallest piece that cannot run without a server; the logic around it stays testable. Do not add an interface and a registration for it: `Every_domain_service_in_the_container_is_listed_as_converted` counts every registered `Domain.*` type as a service. The same holds for a call into a static class whose code reads the database or the native engine for a real player (`Perk.GetPerkLevel`, `StatusEffect.ApplyStatusEffect`): wrap just that call in a `protected virtual` method of the instance class, with the original call as its body (`TrapsService.CanUseTrapTier`, `TrapsService.ApplyBleed`, `MusicService.HasKeyItem`, `WeatherService.GetProtectedDamage`, `FishingService.GiveAgricultureXp`, `LootService.GetPerkLevel`, `LootService.GetStatAdjustment`, `LootService.GetBeastDetail`, `BeastMasteryService.GetPerkLevel`, `BeastMasteryService.ClearCompanionControl`, `ItemService.GetPerkLevel`/`GetPerkName`/`GetCreatureSkillRank`/`GetSkillName` for the perk and skill catalogs, `PropertyService.TogglePlayerWindow` and `CasinoSlotService.TogglePlayerWindow` for `Gui`'s window table, `CapstoneProofService.IsFeatRegistered`/`GetAbilityDetail` for `Ability`'s static ability table, `WardrobeService.ApplyOutfit`/`ApplyHelmet` for the native item writes of `EquippedItemAppearance`), and let a test subclass answer it. The same wrapper fits a call a test cannot wait for or must not make: `PropertyLoaderService.ScheduleLoadBatch` (the load queue's `Scheduler.Schedule`, which runs on the real clock) and `PropertyCityGovernanceService.PropertyBroadcastWebhookUrl` (the webhook the process environment names). Remove the wrapper when the dependency converts. |
| Time, randomness | `Clock` and `Random` as before (`Clock` only in the files the clock seam script owns). A service that compares against `DateTime.UtcNow` and registers `Scheduler` tasks (`ShuttleService`) keeps those calls but puts each behind a one-line `protected virtual` method (`UtcNow()`, `Schedule`, `ScheduleRepeating`) whose body is the original call, so a test can set the time and run the repeating tick and the delayed tasks itself (`ClockedShuttleService` in `Tests/Support/ShuttleBench.cs`). A test of rolls seeds the shared generator (`Random.SetSeed`, `Random.ResetSeed` in `TearDown`) and replays the draws with `System.Random` in the order the service makes them, which also pins their order and number (`FishingServiceTests`). |

Never inject `IServiceProvider` or take the container in a constructor, and a class the container builds never uses `GameServices`. Dependencies that form a cycle between two services cannot be injected both ways: break it by moving the shared part into a third service, or take one direction as `Lazy<IXService>` (`Composition` registers `Lazy<>` once for every service, resolved on the first `.Value`). Use `Lazy<>` only for a real cycle: `LazyDependencyCycleTests` fails for a `Lazy<>` that breaks none. (`IncubationFieldNoteService` takes `Lazy<IBeastMasteryService>` because `BeastMasteryService` takes `IIncubationFieldNoteService`.)

## Tests

- **The instance**: `Tests/Domain/<Domain>/<Name>ServiceTests.cs`. Construct the instance with fakes: `InMemoryDBService` for `IDBService` (entities by id, records every `Set`), `PlayerEngine` (a `FakeNWScript` where the target is a player with a UUID; `Messages()` returns what was sent to the player), `FakePlayerPlugin` and the other plugin fakes for NWNX calls. Assert the saved entities, the messages and the engine calls. `InMemoryDBService` cannot evaluate a query: `Search` and `SearchCount` answer with every stored entity of the type and record the query in `Queries`, so store only what the query would match and assert on the recorded query text. Code that runs several searches over one entity type (the contract board's boot sweep) uses `QueryableDBService` (`Tests/Support`), which wraps an `InMemoryDBService` as `Store` and answers a search with the entities whose indexed properties match the query (exact values, lists of numbers and numeric ranges). A call into a service that is not converted yet (`Item`, `Perk`, `Quest`, ...) runs its real static code, so it works only where that code needs nothing but the engine fakes; code that needs the native engine (`Item.FitsInInventory`) or the database (`Perk.GetPerkLevel` on a player) is left to the in-engine tests, and a DM answer from the engine fake stands in for a player with no perks. The pilot and Economy test classes are the examples.
- **Registration and property**: nothing to write. `ConvertedServiceContainerTests` reads `ConvertedServices.json` and proves for every listed class that the container holds one instance of the instance class, that the instance class has exactly the handlers `HandlerRenames.txt` moved onto it (public, parameterless, `void` or `bool`), that its `GameServices` property returns the installed container's instance, that `GameServices` has no property that is not listed, and that the list names exactly the services `ServiceRegistrations` registers (apart from `IDBService`).
- **Local variables**: the engine fake only records `SetLocalInt` and friends. `Tests/Support/LocalVariables` gives a `FakeNWScript` real local variables (what the code sets is what the matching `GetLocal...` answers until a `DeleteLocal...`); clear the fake's recorded calls through its `ClearCalls`. `Tests/Support/LoadedPlanets` builds a planet instance with its cache filled by the module handler, for tests of the area-to-planet rules.
- **Code that reaches a service without a server**: a unit test of other code (a quest definition that names a guild, a migration that names a market category) calls `GameServices`, which needs a container. Give the fixture a `FacadeContainer` (`Tests/Support`): build it in `[OneTimeSetUp]` (call a cache handler such as `GameServices.Guild.LoadData()` inside `using (container.Install())`), install it in `[SetUp]` and dispose that scope in `[TearDown]`. Without one the call throws `ContainerNotBuiltException`. A test of the code that calls a service, not of the service behind it (the trash can and the destroy item dialog call `ItemTrash.Audit`), replaces that registration: `new FacadeContainer(services => services.Replace(ServiceDescriptor.Singleton<IItemTrashService>(recorder)))`. Window definitions and view models that read the `KeyItem` cache (the Key Items window, `GuiLayoutValidationTests`, `DMToolWindowTests`) need the container too.
- **Roslyn harnesses that borrow a converted service**: a test of code that is not converted yet (the chat routing, the DM toolbar handlers) can compile the service's methods into its own stand-in static class: `InstanceMethod("Domain/<Domain>/<Name>Service.cs", ...)` and `InstanceField(...)` (`DMPossessionHarness`) return the member as a static one, and the stand-in declares static fields for what the instance injects (`_db`, `_presence`) with one-line shims to its own stand-ins. A test whose subject is the converted service itself becomes an ordinary instance test instead: `DMPossessionEngine` (`Tests/Support`) is the harness's model of DM possession behind the engine seams, and `FakeJsonEngine` gives a `FakeNWScript` working `Json` values and templates.
- **Coverage**: at least 70% of the service's lines (the interface and the instance class). Measure with the repository's settings, which exclude generated code:

  ```bash
  dotnet test SWLOR.Game.Server.Tests --no-build -c Release --collect "XPlat Code Coverage" --settings coverlet.runsettings --results-directory <dir>
  ```

  then read `line-rate` per class in the `coverage.cobertura.xml` it writes (or run all projects with `scripts/ci/run-unit-tests.sh --out <dir>`, which merges them). Report the number before the conversion and after it.
- **Behaviour must not change**: `SWLOR.Game.Server.CharacterizationTests` snapshots stay byte for byte; do not regenerate them.

## Rules the architecture tests enforce

`SWLOR.Architecture.Tests` (`ConvertedServicesTests`) reads the compiled server and fails with a message naming the type and member:

- **The pieces exist.** A listed service has the interface `Domain.<Domain>.I<Name>Service`, a class `Domain.<Domain>.<Name>Service` that implements it, and a static property `<Name>` of the interface's type on `Composition.GameServices`; the domain agrees with `DomainMap.json`. The same holds for each listed class of the service (a part has no property).
- **No static state.** No type of a converted service (the interface, the instance class, the types in `Service/<Name>Service/`) holds mutable static state. `const` is allowed, and so is a `static readonly` field of a deeply immutable type (`ConvertedServiceRules.StaticMutableFields`): primitives, `string`, enums, `Regex`, `TimeSpan`, `DateTime` and `Guid`, `System.Collections.Frozen` and `System.Collections.Immutable` collections of such elements, `Nullable<T>` and value tuples of them, and sealed records and record structs whose members are all init-only and of such types. Arrays, `List`, `Dictionary`, `HashSet`, interface types such as `IReadOnlyList<T>`, a class with a settable member and any type the check cannot prove immutable are still reported. A constant table is a `static readonly` field of such a type, never a getter that builds a new value on each read (hot paths read these tables). Frozen collections do not keep insertion order, so a table that callers iterate is an `ImmutableArray` or `ImmutableList` (or an ordered key list beside the lookup), and a public `IReadOnlyList<T>` member returns a private `ImmutableList<T>` field, which allocates nothing per read. A table that needs the engine or a service is not built in a static initializer: it stays in an instance field built by the service.
- **Handlers are on the instance.** A `[NWNEventHandler]` on any type of a converted service that is not one of its instance classes (the main one, a listed class or a listed part) fails.
- **A registered class never uses `GameServices`.** The interface and the instance class of every piece take what they need through the constructor.
- **No service location.** Nothing outside `Composition/` uses `IServiceProvider` or any `Microsoft.Extensions.DependencyInjection` type, or `FacadeAccessor`.
- **Domain types name their service.** A type in `Domain.<Domain>` is classified as the service of that domain whose name starts its name (`IAchievementService`, `AchievementService` and `AchievementNotification` are all the service `Achievement`), so the cross-domain baseline (`CrossDomainEdges.txt`) is the same before and after a conversion. A type that names no service of its domain shows up as a new `Platform/Domain.<Domain>` edge.

The composition root (`Composition/`) names every service it registers, so its outgoing edges are left out of the cross-domain guard (`wiringPlatformAreas` in `DomainMap.json`).

## Reaching a service from static code

| Caller | Reaches the service through |
|---|---|
| A class the container builds (an instance class or part) | Its constructor: the interface, or `Lazy<IXService>` where a direct parameter would make a constructor cycle. Never `GameServices`. |
| Static code: `Feature/`, `Native/`, support types, `Service/` helpers, `SWLOR.CLI` and the other tools, tests | `Composition/GameServices`, a static partial class with one property per service and listed class, named like it and typed as its interface (`public static ITaxiService Taxi => FacadeAccessor.Resolve<ITaxiService>();`, one file per domain, `GameServices.World.cs`). The file imports it with `using static SWLOR.Game.Server.Composition.GameServices;`, so a call reads `Taxi.RegisterTaxiDestination(player, type)`; a project whose `GlobalUsings.cs` imports `SWLOR.Game.Server.Service` globally (`EngineTests`, `SWLOR.Admin`) imports `GameServices` globally too. `Combat`, `Mimicry`, `Performance` and `Prospecting` are also namespace segments, which hide an imported property, so they are written `GameServices.Combat.X`. `Combat`'s members live on 14 parts and `ICombatService`, so a caller names the part: `GameServices.CombatQueries.X`, `GameServices.Combat.X` only for what is on `ICombatService`, and `CombatRules.X` for a pure rule. |
| A constant | The class that holds it (`CombatRules.MaximumHitRate`, `Domain.Quests.FactionService.MinimumFaction`). |
| The script registry | A handler is a public instance method of the instance class. `ScriptRegistry` binds it to the instance a resolver gives for its declaring class: `ServerBootstrapper.LoadScripts` passes `ContainerHost.ResolveHandlerOwner`, the container's singleton of that class (the one `GameServices` returns), so `Core` never touches the container. It binds a handler once, for the class that declares it (a test double that derives from a service registers nothing), and stops the boot with a message for a handler on a class the container does not register. Static handlers of types that are not services bind as before. |

A property costs one read of its per-service slot and one interface call: it allocates nothing (`GameServicesAllocationTests`) and serves the container a test installed (a `FacadeContainer` keeps working).

**Until the cutover**, master still has the static classes the branch deleted, so the sync and the parity run still use the removal tooling. It stays until then:

- `tools/Refactor/RemovedFacades.json` lists each deleted class, and `tools/Refactor/Apply-FacadeRemoval.ps1` (a C# tool, `tools/Refactor/SWLOR.FacadeRemoval`) rewrites master's calls to it: it adds the `using static` line to each caller (or the global form), drops a `Service.` qualifier, writes the explicit names, respells moved constants and renames the manifest lines from `HandlerRenames.txt`. It is idempotent, `-Check` is clean after it (a unit test runs the check on the branch), and the daily sync re-runs it (`MechanicalScripts.txt`), so new master code that calls a deleted class compiles. A tree without `Composition/GameServices.cs` (master) is left alone. Fix by hand what it cannot: `typeof(<Class>)`, `cref`s, and a method group over the old class (a lambda now, or it allocates a delegate on each use).
- **Parity with master.** The parity copy (`MasterCopy.ps1`) runs `Apply-FacadeRemoval.ps1 -Reverse` on its copy of the characterization tests: it drops the `GameServices` imports and those of branch-only namespaces, turns `GameServices.<Name>.` back into `<Name>.` and moved constants back onto their old class. The constants snapshots of `Combat`, `Stat`, `Skill` and `Craft` are explicit lists the reversal can respell. An entry of `tools/Refactor/ClockSeamFiles.txt` for a deleted file stays, marked `# master-only`: the parity copy still rewrites master's version, the branch need not have it, and the sync leaves its conflicts to a person.

## Pitfalls

The entries about one service below were written while the service still had a static facade (`Service.<Name>`); that class is gone. Where an entry says "the facade", read the `GameServices` property or the instance class, and where it says a call "goes through the facade", read "goes through `GameServices`".

- **Name clash.** `Service.<Name>Service` is a namespace (the support types) and `<Name>Service` is also the instance class. Inside `namespace SWLOR.Game.Server.Service` the simple name means the namespace; refer to the interface, or spell the domain namespace.
- **No new support namespaces (owner decision, 2026-11-06).** Do not add a `Service.<Name>Service` namespace that does not exist yet: a new type goes in `Domain.<Domain>`, its name starting with the service's name. The existing ones move in P2-Z2. `Domain.Combat` hides the property `Combat` from other `Domain.*` code: write `GameServices.Combat.X` there.
- **Runtime state in `Feature/` static classes.** The class stays where it is and keeps its `[NWNEventHandler]` methods and stateless logic, so handler names and the manifest do not change. Its runtime state (per-player dictionaries, cooldowns, schedules, caches) moves to an instance service: an existing service of that domain when one owns the subject, otherwise a new one with the usual pieces (`Domain.<Domain>.I<Name>Service`, `<Name>Service`, registration, `GameServices` property, `ConvertedServices.json`, `DomainMap.json`). The `Feature` class calls the property. A table that nothing writes after it is built becomes a `static readonly` field of a deeply immutable type and stays in the class.
- **Package.** `Microsoft.Extensions.DependencyInjection` 9.0.9 is the version the toolset already uses (`SWLOR.Toolset.csproj`); `SWLOR.Game.Server/packages.lock.json` and the lock files of the toolset projects that reference the server record it. Change the version everywhere at once, then `dotnet restore <project> --force-evaluate` (add `-p:Configuration=Release` for the `packages.Release.lock.json` files) for the server and each toolset project.
- **Test projects see `Domain` as a namespace.** A test namespace `...Tests.Domain.<Domain>` is fine; spell the production types with a `using SWLOR.Game.Server.Domain.<Domain>;`.
- **Engine structures.** Production code that makes a real engine structure (`new Location(IntPtr.Zero)`) crashes a unit-test process when the garbage collector finalizes it, because the finalizer calls the native library. Fakes avoid this (`EngineStructures.Create`); for a structure the service makes itself, put the construction in a `protected virtual` method and override it in the test (`ChatCommandService.CreateEmptyLocation`).
- **Shared statics the instance reaches.** A converted instance still calls services that are not converted. Their static state is shared between tests: `Scheduler.Schedule` leaves an item that another test's `Scheduler.Process()` runs against whatever engine is installed then (drain it with `Scheduler.Process()` in `TearDown` while your fake is installed), and `Authorization.GetAuthorizationLevel` and `Disguise`/`PlayerName` lookups of a real player read the static `DB`. A test that must pass them uses an object the fake engine reports as a non-player, or `SWLOR_SUPER_ADMIN_CD_KEY` set for the test to the CD key the fake returns.
- **Engine tests that called private statics by reflection** (`typeof(Party).GetMethod("AddToParty", ...)`) reach the instance through `EngineTests/Framework/PartyCaches.cs`, which reads `CompositionRoot.ServerHost.Provider`. Tests outside the server assembly may do that; the architecture rule is about the server assembly.
- **Offline callers.** A pure method of a converted service (`PlayerMarket.GetBaseItemMarketCategory`, which an offline migration calls) still goes through the facade and so needs the container. The server's boot builds it before any handler; tests install a `FacadeContainer`. The module editor (`SWLOR.Toolset`) has no container at all: it must not call a facade member at run time. The one it used (`Item.IsEconomyRestricted(BaseItem, ...)`, the data-only economy classifier) moved into a stateless static helper beside the service (`Domain/Items/EconomyRestriction.cs`, no fields, no handlers), which the instance calls and the editor calls directly. Before converting a service, search `SWLOR.Toolset*`, `SWLOR.CLI` and `SWLOR.CombatSim` for its members.
- **Private constants and tests that read them.** A test that reflected on a private member of the old static class (`Bank.StorageId`) follows it to the instance class; a test that read the old file's text (`LeadershipCivicPerkRegressionTests` reading `Guild.cs`) follows the code to `Domain/<Domain>/`.
- **Members the unit tests cannot reach.** A call into a not-yet-converted service that needs the native engine or the static database cannot run offline: `Gui.TogglePlayerWindow` (its window table), `Space.IsPlayerInSpaceMode` (`DB.Get`), the `NWNXLib` structures that `DMPresence.GetIsManifested` reads, and the player list `Area` fills in an event handler. The instance tests leave those lines to the in-engine tests, and the window logic around them stays covered by the harness tests of the code that shows the windows (the DM toolbar, the emotes window) through `InstanceMethod`.
- **Out parameters and engine structures on a facade.** `RecordingProxy` writes a default into an `out` value-type parameter (an `out bool` otherwise fails the proxy's write-back) and suppresses the finalizer of an engine structure it returns (`Json`, `Location`), which would crash a process with no engine.

## A service of several classes

Most services are an interface and an instance class. A service can be more than that, and lists the other classes under `"extras"` on its `ConvertedServices.json` entry. There are two kinds of extra, and one rule set for both:

```json
{ "name": "Quest", "domain": "Quests", "extras": [ { "class": "QuestEncounter" } ] }
{ "name": "Property", "domain": "World", "extras": [ { "part": "PropertyCatalog" }, { "part": "PropertyCityGovernance" }, { "part": "PropertyLoader" } ] }
```

- **A class** (`"class"`, a plain type name) is a further class of the service that static code reaches through a `GameServices` property of the same name (`GameServices.QuestEncounter`). It keeps its own handlers and state, as an instance class with its own interface.
- **A part** (`"part"`, a plain name) is a class a large service is split into by responsibility. Static code does not reach it unless the service's members were spread over its parts so that no call passes through a second instance (`Combat`: its 14 parts each have a `GameServices` property).

Either kind is named after its type `<Type>`: the instance class is `<Type>Service` behind `I<Type>Service`, in the domain namespace of the service, registered in `ServiceRegistrations` and counted as a service of the container. The type name must start with the service name followed by a capital letter (`QuestEncounter`, `PropertyCatalog`) so the cross-domain guard counts the classes as the same unit and the baseline does not change; the list test says so when it does not, and when an extra is the service's own class. The list is sorted by name, and a leftover `"facade"` key or `"facadeRemoved"` flag is reported.

The rules apply to every class of the service: the interface and instance class exist (a class also has its `GameServices` property), no static state, handlers only on an instance class of the service, no use of `GameServices` by a registered class, no service location. `ConvertedServiceContainerTests` runs its checks for every class, parts included: one singleton per class, the handlers `HandlerRenames.txt` moved onto it, the property of each class that has one, the registered services exactly the listed ones.

### Further classes

A further class is converted exactly like a service of its own:

- The interface and the instance class sit in the domain namespace of the service (`Domain/Quests/IQuestEncounterService.cs`, `QuestEncounterService.cs`); the instance class keeps the class's handlers and state.
- Add its property to `GameServices.<Domain>.cs` and list it in `tools/Refactor/RemovedFacades.json` like the old static class.
- Two instances of one service may need each other. They cannot both take the other by constructor; inject in one direction (`QuestService` takes `IQuestEncounterService`) and take the other as `Lazy<IQuestService>`.
- The list test fails with a message for a name that is not a plain type name, a duplicate or unsorted name, and a missing interface, instance class or property.

The pitfalls and test patterns are the same as for a service: the tests that read the old file's source read the instance class (`Domain/Quests/QuestService.cs`), and the engine tests reach the private members of an instance through the container (`EngineTests/Framework/QuestInternals`).

### Parts

A service of a few thousand lines is converted as several parts (`Property`: the definitions catalog, the instance loader, the city governance and the service itself). `IPropertyService` has exactly the old class's public members.

- **Ownership.** Static state moves to the part that owns it; a part that must clear another part's state for one key gets a small method for it (`PropertyLoaderService.ForgetProperty`, the verbatim lines `DeleteProperty` used to run). Members of a part that other parts call are public members of its interface; the rest stay private.
- **No cycles.** Parts depend on each other through constructor-injected interfaces, and the dependency graph must be a tree (`PropertyService` takes the catalog, the loader and the city governance; the loader and the governance take the catalog; the catalog takes `IAreaService`). Where two classes would need each other, one of them takes the other as `Lazy<IXService>`, which resolves at call time; a support type the container does not build (`StructureChangedAction`, of `Property`) calls `GameServices.Property`. A part has no `GameServices` property of its own unless the service spread its members over its parts (`Combat`).
- **Forwarding.** `PropertyService` implements every member of `IPropertyService`: the ones it owns hold the logic, the others are one-line forwards to the part (`return _loader.GetPropertyLoadState(propertyId);`). Logic that calls a member another part owns calls the part's interface (`_catalog.GetLayoutByType`), or its own forward when it is public on the service. A service whose members run per swing or per hit instead spreads them over its parts and gives each part its own `GameServices` property, so a call passes through no second instance (`Combat`: `GameServices.CombatQueries.GetRelevantSkillWeapon(...)`), and the main interface holds only what the main instance owns. A pure rule of the service's static `Domain.<Domain>.<Name>Rules` class (`CombatRules`) is called directly.
- **Tests.** Test each part against its own fakes, and the service with the real parts over one scripted world (`Tests/Domain/World/PropertyWorld` builds the engine fake, a `QueryableDBService`, the area and planet stand-ins, the real catalog and the other parts, with the seams above replaced). A part's constructor is as free of work as a service's.
