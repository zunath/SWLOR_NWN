Item editor — Design A

The item editor (.uti), in the shape the door, placeable, trigger and waypoint editors ship: header is name · kind · resref, tabs are Basic / Appearance / Behavior / Stats / Requirements / Source, the left column holds the live preview on every tab, and Variables appears only under Custom. The base type chosen on Basic organizes everything after it: it decides the Appearance surface, which roles the Behavior rail offers, and which stat groups the Stats tab shows. Field data is verified against Module\uti (7,651 blueprints) and the pr/2124 hak data.

Roles — the Behavior tab

Equipment never reaches this tab's rail; the carriable families do, and the rail lists only the roles the base type supports. Choosing a role is what unlocks that role's stats on the Stats tab, and each role manages the values that follow from it.

Requirements and Source — the shared tabs

These two are the same shape for every family. Requirements is skills by category plus stat, perk and race gates; Source lists every place a player can obtain the item, from a resref-keyed index built once per workspace and refreshed per saved file.

Implementation notes

Two requirements ship with the first build: the stat grid must read itempropdef.2da and its cost tables so no property is ever shown as numbers (DMG's CostTable 34 points at iprp_dmg.2da, not iprp_damagecost.2da — the known trap); and the Source tab must reuse EconomyObtainabilityCoverageTests' source extraction as a workspace index — one background pass over stores, recipes, loot tables and placed containers at load, keyed by resref and re-scanned only for files that change — so the tab answers in constant time and can never disagree with the test. An item with no sources shows the empty Source rows, which is also exactly when it needs the No Economy flag on Basic.

The Variables tab follows the waypoint editor's rule: it exists only while the behavior is Custom, so the 2,066 items carrying locals stop being ambient state — a declared role surfaces its locals as named fields, and only the unclassified remainder edits them raw.

Two earlier design studies — an Aurora-faithful five-tab editor and a one-page grouped editor — were weighed and set aside in favor of this one; they live in this file's git history.
