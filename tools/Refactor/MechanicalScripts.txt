# Mechanical scripts of the maintainability refactor: re-runnable rewrites that turn master's code into the refactor
# branch's shape (the clock seam; later the NWScript generator, P1-1). One repository-relative script path per line,
# run in this order. Read by Sync-MaintainabilityBranch.ps1 (which re-runs every script after merging master and takes
# master's version of a conflicted file a script owns) and by Test-MaintainabilityParity.ps1 (which runs every script
# on its throwaway copy of master). A new mechanical script is added with one line here.
#
# Contract for a script (Apply-ClockSeam.ps1 is the reference):
#   -File <script> [-RepositoryRoot <root>]            apply the rewrite; idempotent (a second run changes nothing)
#   -File <script> [-RepositoryRoot <root>] -Check     change nothing; exit 1 when a run would change something
#   -File <script> [-RepositoryRoot <root>] -ListOwnedFiles
#                                                      print, one per line, the repository-relative paths (forward
#                                                      slashes) of the files the script owns; a trailing /** means
#                                                      every file under that folder. Prints nothing else, exits 0.
# Exit code 0 is success. The scripts must run under Windows PowerShell 5.1 and PowerShell 7.
#
# Apply-ContentInjection.ps1 (P5-13) runs right after Apply-FacadeRemoval.ps1: it converts the content files it lists from the shape
# the facade removal leaves (GameServices calls) to constructor injection, and rewrites master's new creations of converted content.
# It converts nothing while tools/Refactor/ContentInjection.json lists nothing, and changes nothing on a tree without
# SWLOR.Game.Server/Core/IContentFactory.cs (master, the parity copy).
# Move-SupportNamespaces.ps1 (P2-Z2) runs after Apply-FacadeRemoval.ps1: the removal finds master's calls to a removed
# facade by master's namespaces (Service.<Name>Service), which the move then rewrites to Domain.<Domain>.
# Move-ServiceTypes.ps1 (P2-Z3) runs next: master code still names the types left directly in Service (through a using of
# Service, the enclosing namespace or a qualified name), and the files Move-SupportNamespaces.ps1 moves out of a
# Service.<Name>Service folder keep reaching them through Service, so it moves every such reference to the types' domains.
# Move-DomainOrderTypes.ps1 (P5-1c) runs after it: master names the domain order's type moves
# (tools/Refactor/DomainOrderTypeMoves.json) through Service.<Name>Service, which Move-SupportNamespaces.ps1 first turns into
# Domain.<Domain>; only then can it send Domain.<Domain>.<Type> on to its lower domain. A P2-Z3 type that moves again
# (Log, FrameProfiler) has its TypeMoves.json entry point at its last namespace, so Move-ServiceTypes.ps1 still finds it.
#
# "Owns" means the branch's only change to the file is the script's rewrite, so on a merge conflict in an owned file
# the sync takes master's version and runs the script again instead of merging by hand.
